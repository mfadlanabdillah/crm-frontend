# Agent recipes

Step-by-step procedures per task type. Rules and boundaries live in [AGENTS.md](../../AGENTS.md).
Each recipe ends with **Done when**; run that command and report the result as it is.

Living references: module `case` (`apps/crm-agent/src/modules/case/`) and `customer`.

## Add an API endpoint

1. Add the path and schema to `packages/api-client/openapi/openapi.yaml`. Business codes (status, queue, priority) are plain `string`; their values come from master data, not an OpenAPI enum.
2. Run `pnpm codegen:api` (it writes `packages/api-client/src/generated/openapi.d.ts`; never edit that file).
3. Export the type and add a method to `createApiClient` in `packages/api-client/src/index.ts`, wrapped in `unwrap(...)` like the others so errors become `ApiError`.
4. Wrap it in the module facade `apps/crm-agent/src/modules/<id>/api/<id>.ts`. Components never call `api` directly.
5. Add a query hook in `modules/<id>/queries/` using `queryOptions` and centralized keys (`caseKeys` in `src/lib/query-keys.ts`, or the module's `queries/keys.ts`). Example: `useMasterData.ts`.
6. Dev mock: data in `src/mocks/db.ts`, handler in `src/mocks/handlers.ts`. Mask PII per role through `src/mocks/mask.ts`.
7. Tests: client logic in `packages/api-client/src/index.test.ts`; components that use it with `renderWithProviders` from `@crm/test-utils` (seed the cache with `queryClient.setQueryData`).

**Done when:** `pnpm codegen:api` leaves no uncommitted diff and `pnpm check` is green.

## Add a CRM module

1. Run `pnpm new:module <id> --path /<path> --icon <LucideIcon> --permission <module.action>`. It creates `modules/<id>/`, a thin route with a permission guard, and the entry in `src/app/modules/registry.ts`.
2. Add the permission in `packages/auth/src/roles.ts` (the `Permission` type and the per-role lists).
3. Add `<id>.title` (and other text) to `packages/i18n/src/resources.ts`, both locales.
4. Contract, facade, query, and mock: follow "Add an API endpoint".
5. Expose things to other modules only through `modules/<id>/public.ts` (queries, schemas, store; never components).

**Done when:** `pnpm check` is green and `pnpm test:e2e` passes (the module shows in navigation for roles that may see it).

## Add a page or route

1. Page body goes in `modules/<id>/pages/`. The route file in `src/routes/_authenticated/...` holds only `validateSearch`, the guard (`requirePermission` from `@/app/auth/guard`), and the page component.
2. Filters and pagination in the URL: a zod schema with `.catch()` for stale values and `stripSearchParams(DEFAULT_...)` to keep URLs short (see `modules/case/schemas/search.ts`).
3. `routeTree.gen.ts` is regenerated by `pnpm dev`; never edit it.
4. Pages that pull in a heavy library use `lazy()` + `Suspense`.

**Done when:** `pnpm check` is green and `pnpm size` shows the new route under 300 KB gzip.

## Add UI text

1. Add the key to `packages/i18n/src/resources.ts` in both `id-ID` and `en-US`, with the same structure and `{{...}}` placeholders.
2. Use `t('key')` from `react-i18next`; no display strings inline in JSX.
3. Status, queue, and priority labels are not i18n text: they come from `GET /v1/master-data`.

**Done when:** `pnpm exec vitest run packages/i18n` is green (locale parity test).

## Add or change a permission

1. Add the name to the `Permission` type and to the roles that hold it in `packages/auth/src/roles.ts`.
2. UI: `can('x')` or `<Can permission="x">`. Route: `beforeLoad: requirePermission('x')`. Module: `permission: 'x'` in `module.ts` hides its navigation.
3. This only controls the UI; the server stays the final gatekeeper.

**Done when:** `packages/auth/src/roles.test.ts` covers the new permission and `pnpm check` is green.

## Show personal data (PII)

1. The server already masks; the UI still calls `maskPhone`/`maskEmail`/`maskAddress` from `@crm/auth` with the current role.
2. Never write PII to logs, error messages, or test fixtures; use fake data (`example.com`).
3. The server-imitating mock is `src/mocks/mask.ts`; update it when a field shape changes.

**Done when:** a masking test covers the new field (`packages/auth/src/pii.test.ts` or `src/mocks/mask.test.ts`).

## Errors, expired sessions, and logout

- API errors become `ApiError` (`status`, `code`, `requestId`). Show them with `ErrorState` (`components/ui/data-state.tsx`); the message may come from the server, never show a stack trace.
- A 401 from any query or mutation is handled globally (`lib/query-client.ts` calls the handler installed by `app/auth/session-expiry.ts`): client data is cleared and the app goes to `/login?redirect=...`. Do not add per-page 401 handling.
- A module cleans its state through `onSignOut(reason)` in `module.ts`. `expired` may keep unsent work (example: `modules/case/store/drafts.ts`); `logout` must delete it.
- Render errors are caught by `RouteError` (`app/layout/RouteFallbacks.tsx`) and reported through `reportError` in `lib/telemetry.ts`. Plug in an SDK with `setErrorReporter`.

**Done when:** the new behavior has a unit test and, if it changes the session flow, an e2e (`apps/crm-agent/e2e/case-workspace.spec.ts` is the example).

## Write tests

- **Unit/component:** `*.test.ts(x)` next to the code. For components using queries, use `renderWithProviders` from `@crm/test-utils` and seed the cache with `setQueryData`. For i18n text, `await createI18n()` in `beforeAll`.
- **Router:** build a memory router (`createMemoryHistory`) as in `app/layout/RouteFallbacks.test.tsx`.
- **E2E (Playwright, `apps/crm-agent/e2e/`):** dev server with MSW. After signing in, navigate through the router (`clientNavigate`), never `page.goto`. Wait for `networkidle` before ending the session.
- **Accessibility:** add new pages to `e2e/a11y.spec.ts`; `expectNoViolations` must stay clean.
- The coverage floor is in `vitest.config.ts`; raise it when tests grow.

**Done when:** `pnpm check` and, for UI/flow changes, `pnpm test:e2e` are green.

## Change dependencies, CI, or Docker

Only when asked. Pin exact versions (`.npmrc` already has `save-exact`), prefer releases older than two weeks, and explain why. After editing `package.json`, run `pnpm install` and commit `pnpm-lock.yaml`. For the image: `docker build -t crm-agent .`, then `docker run --rm crm-agent nginx -t` must succeed.

**Done when:** `pnpm install --frozen-lockfile` and `pnpm check` are green.
